# 오늘의 부적

생년월일과 운세 종류로 행운 키워드 8개를 뽑고, 키워드 스티커를 부적 틀에 붙여 나만의 부적 이미지를 만드는 모바일 우선 웹앱.
빌드 도구, 프레임워크, 서버 없이 **순수 HTML·CSS·JavaScript**로 동작한다.

---

## 실행 방법

이미지를 캔버스로 합쳐 저장하는 기능 때문에 **웹 서버로 열어야 한다.** (`index.html`을 파일로 바로 열면 저장·터치 판정이 막힘)

```bash
cd charm-app
python3 -m http.server 8000      # 또는 npx serve
# 브라우저에서 http://localhost:8000
```

배포는 폴더 전체를 정적 호스팅(Firebase Hosting, Cloud Storage, GitHub Pages, Netlify 등)에 올리면 끝.

## AI 스튜디오(또는 다른 AI 도구)에 올릴 때

이미지 504장까지 한꺼번에 올리면 AI가 읽을 수 있는 양을 넘어 **"maximum number of tokens" 오류**가 난다. 그래서 두 묶음으로 나눈다.

- **코드 묶음** (`charm-app-code.zip`, 약 100KB): `index.html`, `styles.css`, `app.js`, `data/`, `README.md` → **AI 도구에는 이것만 올린다**
- **이미지 묶음** (`charm-app-assets.zip`, 약 26MB): `assets/` → AI에게 보여줄 필요 없음. 실제로 실행·배포할 때만 같은 폴더에 합치거나, 다른 곳에 올리고 `data/config.js`의 `ASSET_BASE`에 주소를 넣는다

이미지를 다른 곳에 두는 예 (GitHub 저장소 + jsDelivr, 무료):
1. GitHub에 저장소(예: `charm-assets`)를 만들고 `assets/` 폴더를 그대로 올린다
2. `data/config.js`를 `window.ASSET_BASE = "https://cdn.jsdelivr.net/gh/{아이디}/charm-assets@main";` 로 바꾼다
3. jsDelivr는 CORS를 허용하므로 저장 기능까지 그대로 작동한다

AI에게 수정을 맡길 때도 한 번에 모든 파일을 붙여넣지 말고, 고칠 파일만 골라 보여주는 편이 안정적이다. (`reference/`의 원본 데이터는 참고용이라 올릴 필요 없음)

## 폴더 구조

```
index.html              화면 구조 (홈, 입력, 결과, 꾸미기, 나의 부적, 모달)
styles.css              디자인 (라이트/다크 대응, 모바일 우선, 900px 이상에서 2단)
app.js                  기능 전부 (뽑기, 편집기, 저장, 보관함)
data/config.js          이미지 주소 설정 (ASSET_BASE)
data/fortune-data.js    키워드 데이터 → window.APP_DATA
data/frame-themes.js    부적 틀 테마 설정 → window.FRAME_THEMES
assets/stickers/{카테고리}/{키워드id}-{스타일}.webp   스티커 486장 (162종 × 3스타일)
assets/frames/{테마id}/{운세id}.webp                  부적 틀 18장 (3테마 × 6운세)
reference/fortune-master.js   원본 마스터 데이터 (태그, AI 이미지 프롬프트용 영문 소재 포함)
```

## 화면 흐름

1. **홈**: 시간대에 따라 문구가 바뀜. 저녁 6시(`NIGHT_FROM`) 이후에는 "내일의 부적"으로 안내
2. **입력**: 날짜(오늘/내일), 운세 종류 6개, 생년월일(선택, "생일 없이 뽑기" 가능)
3. **결과**: 키워드 8개 + 조사까지 맞춘 한 줄 문장. 다시 뽑기는 날짜별 2회
4. **꾸미기(편집기)**
   - 아래 트레이에서 스티커를 누르면 카드에 붙음 (같은 스티커 여러 장 가능)
   - 트레이 위 스타일 버튼(Y2K 팝/레트로/두들)은 **트레이에만** 적용. 붙인 스티커는 각자 스타일을 유지
   - 스티커를 누르면 위에 **편집 막대**가 따라다님: 앞으로·뒤로·회전·스타일 변경·삭제
   - 분홍 손잡이로 크기와 각도 조절
   - **일괄 편집**: 붙인 스티커 스타일 한 번에 바꾸기 / 키워드 8개 세트 붙이기 / 모두 지우기
   - **틀**: 운세는 고정, 같은 운세 안에서 틀 테마만 바꿈. 바꾸면 스티커가 새 틀의 같은 상대 위치로 옮겨짐
   - 되돌리기(최대 30단계), 자동 임시 저장
5. **저장**: PNG 다운로드, 나의 부적(브라우저 저장소, 최대 24개)에 보관, 공유(지원 기기만)

## 핵심 규칙 (수정할 때 지켜야 할 것)

- **같은 입력 → 같은 결과**: 키워드는 `생년월일 해시 | 운세 | 날짜 | 다시뽑기 회차`를 시드로 한 결정적 난수로 뽑는다(`drawKeywords`). 생년월일 원문은 어디에도 저장하지 않고 해시만 쓴다.
- **가중치 뽑기**: 각 키워드의 `weights[운세id]`(1~5)에 비례. `EX`에 있는 조합은 한 부적에 같이 나오지 않음.
- **카드 좌표계**: 가로 1080 고정, 세로는 틀 비율로 계산(Y2K 1919, 레트로·두들 1620). 스티커 위치·크기는 이 좌표로 저장하고, 화면에서는 비율 `K = 실제 폭 / 1080`으로 그린다. 저장 이미지는 이 좌표 그대로 1080 폭으로 출력.
- **스티커 객체**: `{ uid, ref: 카테고리|"deco", id, st: 스타일|null, x, y, s: 크기배율, r: 각도 }`. 원본 이미지는 320 단위(`BASE`)로 그린다.
- **브라우저 저장소 키**: `charm:draft:v3`(작업 중), `charm:saved`(보관함), `charm:round:{날짜}:{해시}:{운세}`(다시 뽑기 횟수). 구조를 바꾸면 키 버전을 올릴 것.
- **스티커 그림자 없음**: 스티커는 부적에 붙은 느낌이어야 해서 그림자를 넣지 않는다.
- **문구 톤**: 존댓말, 짧고 다정하게. 버튼은 동사형("저장", "붙이기").

## 확장 방법

**부적 틀 테마 추가**
1. 운세 6개 틀 이미지를 흰 배경으로 만들고, 배경·고리 구멍을 투명 처리해 `assets/frames/{새테마id}/{운세id}.webp`에 넣는다
2. `data/frame-themes.js`에 항목 추가 (`size`, `fortunes`, `area`, `text`, `colors`). 레트로 항목을 복사해 값만 조정하면 됨
3. 테마가 2개 이상이면 꾸미기 화면에 선택 버튼이 자동으로 나타남

**스티커 스타일 추가**
1. 162종 이미지를 `assets/stickers/{카테고리}/{id}-{새스타일}.webp`로 넣는다 (정사각, 투명 배경, 흰 다이컷 테두리)
2. `index.html`의 스타일 버튼 3곳(트레이 `#style-seg`, 편집 막대 `#ftb`, 일괄 편집 `#bulk-style`·`#bulk-add`)과 `app.js`의 `STYLE_NAME`에 추가

**키워드 추가/수정**: `data/fortune-data.js`의 `DATA`에 항목을 넣고, 같은 id로 스티커 이미지 3장을 넣는다.

## AI에게 수정을 요청할 때 (Gemini용 지침)

- 이 프로젝트는 **순수 HTML/CSS/JS**다. React 등으로 바꾸거나 빌드 도구를 넣지 말고 기존 파일 구조를 유지한 채 수정할 것
- 이미지를 코드 안에 base64로 넣지 말 것. 항상 `stickerPath()`나 `ASSET_BASE` + `assets/` 경로로 참조
- 새로 만드는 `<img>`는 `newImg()`로 만들 것 (다른 주소의 이미지도 캔버스 저장이 되도록 CORS 설정 포함)
- 키워드·틀 설정은 `data/` 파일에서, 동작은 `app.js`에서 수정
- 모바일(폭 390px 전후) 터치 사용을 먼저 고려할 것. 편집 막대·손잡이·트레이는 손가락으로 누르기 쉬운 크기(36px 이상) 유지
- 위 "핵심 규칙"을 깨는 변경(결정적 뽑기, 좌표계, 저장 키)은 이유를 먼저 설명하고 진행
